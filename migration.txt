================================================================================
MIGRATION SUMMARY: HOSTING 15-440 WEBSITE VIA GITHUB.IO (GITHUB PAGES)
================================================================================

1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The CMU 15-440 Distributed Systems course website is a static site built using 
Jekyll (v4.3.x) and a custom embedded theme located in `doks-theme/`. 
Currently, the site is deployed via a GitHub Actions workflow (`.github/workflows/deploy.yml`) 
that compiles the Jekyll site and uses SSH/rsync (`AEnterprise/rsync-deploy`) to push 
the compiled output (`_site/`) to an external university server (`COMPSYS`/`UNI`).

Migrating the website to be hosted directly via `github.io` (GitHub Pages) requires 
changes across four main areas:
  A. CI/CD Workflow: Transitioning from SSH/rsync deployment to GitHub Pages Actions.
  B. Site Configuration & URL Routing: Updating `baseurl` and `url` parameters.
  C. Theme & Template Links: Unifying URL helper logic and eliminating hardcoded paths.
  D. Markdown Content & Asset References: Fixing relative links and missing assets.


2. GITHUB ACTIONS WORKFLOW MIGRATION (.github/workflows/deploy.yml)
--------------------------------------------------------------------------------
The current workflow deploys to an external server using secrets that will no 
longer be needed, and uses deprecated action versions and Ruby 2.6 (which is 
unsupported on current GitHub Actions runner images).

Required Changes:
  1. Replace the external rsync deployment step with standard GitHub Pages deployment 
     actions (`actions/configure-pages@v5`, `actions/upload-pages-artifact@v3`, and 
     `actions/deploy-pages@v4`).
  2. Add workflow permissions:
       permissions:
         contents: read
         pages: write
         id-token: write
  3. Add concurrency control to prevent conflicting simultaneous deployments:
       concurrency:
         group: "pages"
         cancel-in-progress: false
  4. Upgrade Actions and Runner environment:
     - Upgrade `actions/checkout@v2` to `actions/checkout@v4`.
     - Upgrade `ruby/setup-ruby@v1` to use a supported Ruby version (e.g., `ruby-version: '3.2'` 
       or `'3.3'`) with `bundler-cache: true`. (Ruby 2.6 is deprecated/removed on modern runners).
  5. Update Jekyll Build Step:
     - Replace `--baseurl "/15-440/fa2025"` with the dynamic base path from 
       `steps.pages.outputs.base_path` or configure it via `_config.yml`.
     - Retain `JEKYLL_ENV: production`.
  6. Remove Obsolete Secrets and Steps:
     - Remove `AEnterprise/rsync-deploy` step and references to secrets:
       `COMPSYS_SERVER_SSH_KEY`, `COMPSYS_SERVER_PORT`, `COMPSYS_SERVER_IP`, 
       `COMPSYS_USERNAME`, `COMPSYS_SERVER_DESTINATION`, `UNI_*`.
     - Remove commented-out Kerberos client steps.


3. JEKYLL CONFIGURATION (_config.yml)
--------------------------------------------------------------------------------
Required Changes:
  1. Site URL & Baseurl:
     - Set `url`: Add `url: "https://<owner>.github.io"` (or custom domain if used).
     - Set `baseurl`:
       * If hosted as a Project Page (e.g. `https://<org>.github.io/<repo>/` or 
         `https://<user>.github.io/15-440-website/`): Set `baseurl: "/<repo-name>"`.
       * If hosted as a User/Org Root Page (`https://<org>.github.io`) or with a 
         custom domain (e.g. `https://15440.courses.cs.cmu.edu`): Set `baseurl: ""`.
  2. Unify `doks.baseurl` with `baseurl`:
     - Currently `_config.yml` defines `doks.baseurl: "/15-440/fa2025/"` (with trailing slash) 
       while root `baseurl` is `""`.
     - Because navigation templates concatenate `site.doks.baseurl` with `/syllabus`, 
       a trailing slash produces malformed double-slash URLs (`//syllabus`).
     - Remove `doks.baseurl` or align it with `site.baseurl` (without trailing slash).
  3. Course Links & Metadata:
     - Verify and update course URLs (Edstem, Canvas, OHQueue, PollEv, Gradescope) 
       for the active academic term.
  4. Missing Headshot Asset in `_config.yml`:
     - Line 242 references `image: tsmehta.jpg` for TA Tanisha Mehta, but 
       `doks-theme/assets/images/headshot/tsmehta.jpg` is missing from the repository.
     - Add `tsmehta.jpg` or fallback to `silhouette.png` to avoid a 404 image request.


4. THEME TEMPLATES & LAYOUTS (doks-theme/)
--------------------------------------------------------------------------------
Required Changes:
  1. Header Navigation Link Generation (`doks-theme/_includes/site-header.html`):
     - Lines 5 & 29 use `{{ site.doks.baseurl }}{{ item.item_url }}` while the rest 
       of the site uses `{{ site.baseurl }}`.
     - Update to use `{{ site.baseurl }}{{ item.item_url }}` or standard Jekyll 
       Liquid filter `{{ item.item_url | relative_url }}` to guarantee link consistency.
  2. Baseurl Prepends in Layouts:
     - `doks-theme/_layouts/default.html`, `homepage.html`, `error-404.html`, 
       `site-head.html`, `site-footer.html`, `staff.html`, `instructor.html`, `micro-nav.html`:
       All templates currently use:
         `{% if jekyll.environment == 'production' %}{{ site.baseurl }}{% endif %}...`
       Ensure `JEKYLL_ENV: production` is always set during GitHub Actions build, 
       or refactor to Jekyll's built-in `| relative_url` filter (e.g. `{{ '/assets/...' | relative_url }}`) 
       which automatically handles `baseurl` in both development and production.


5. MARKDOWN CONTENT FILES & LINK PATHS
--------------------------------------------------------------------------------
Several Markdown files contain hardcoded relative paths (`../`) that will fail 
under GitHub Pages subpath routing (`/:title/` permalink structure):

Required Changes:
  1. `assignments.md` (Line 21):
     - Current: `<script type="text/javascript" src="../assets/js/skedj.js"></script>`
     - Change to: `<script type="text/javascript" src="{{ site.baseurl }}/assets/js/skedj.js"></script>` 
       (or `{{ '/assets/js/skedj.js' | relative_url }}`).
  2. `schedule.md` (Line 20):
     - Current: `<script type="text/javascript" src="../assets/js/skedj.js"></script>`
     - Change to: `<script type="text/javascript" src="{{ site.baseurl }}/assets/js/skedj.js"></script>`
  3. `past-exams.md` (Line 16):
     - Current: `- [Midterm I solution for Fall 2020](../assets/midterm1_2020.pdf)`
     - Change to: `- [Midterm I solution for Fall 2020]({{ site.baseurl }}/assets/midterm1_2020.pdf)`
  4. `recitations.md` (Line 14):
     - Current: `...only when shown on the [schedule](../schedule).`
     - Change to: `...only when shown on the [schedule]({{ site.baseurl }}/schedule)`


6. DATA SOURCES, CORS & THIRD-PARTY INTEGRATIONS
--------------------------------------------------------------------------------
  1. Google Sheets Schedule / Assignment Feeds (`schedule.md` & `assignments.md`):
     - Both files fetch live course data via `skedj.js` using:
       `https://heather-cors.herokuapp.com/https://docs.google.com/spreadsheets/...`
     - The third-party Heroku CORS proxy (`heather-cors.herokuapp.com`) should be verified.
       Google Sheets published CSV links (`https://docs.google.com/spreadsheets/d/e/.../pub?output=csv`) 
       now provide CORS headers (`Access-Control-Allow-Origin: *`) directly over HTTPS, 
       allowing the proxy prefix to be removed or replaced with a reliable proxy / static fallback.
  2. Third-Party CDNs:
     - Google Fonts (`fonts.googleapis.com`), Skedj table CSS (`unpkg.com`), and 
       Google Calendar embed (`calendar.google.com`) are loaded over HTTPS and will 
       work seamlessly on `github.io`.


7. DEPENDENCIES & RUBY ENVIRONMENT (Gemfile & Gemfile.lock)
--------------------------------------------------------------------------------
  1. Jekyll Version & Deployment Strategy:
     - The project uses `jekyll ~> 4.0` (specifically 4.3.3).
     - Standard GitHub Pages native automated builder (legacy) only supports Jekyll 3.9.x.
     - Using **GitHub Actions** (`deploy-pages`) compiles Jekyll 4.x in the runner before 
       deploying static artifacts to GitHub Pages, so no gem downgrades are required.
  2. Bundler / Ruby Compatibility:
     - When running on Ruby 3.x in GitHub Actions, Bundler will automatically utilize 
       the `webrick` dependency defined in `Gemfile.lock`.


8. GITHUB REPOSITORY & DOMAIN CONFIGURATION
--------------------------------------------------------------------------------
Required GitHub Settings:
  1. Repository Settings -> Pages:
     - Under "Build and deployment" -> "Source", select **GitHub Actions**.
  2. Custom Domain (Optional):
     - If hosting under a custom domain (e.g., `15440.courses.cs.cmu.edu` instead of `*.github.io`):
       * Add a `CNAME` file containing the domain name at the repository root.
       * Configure DNS CNAME record pointing to `<owner>.github.io`.
       * Enable "Enforce HTTPS" in repository settings.
